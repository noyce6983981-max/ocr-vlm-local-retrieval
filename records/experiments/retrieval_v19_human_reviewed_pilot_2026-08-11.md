# V19 人工审核先导路由实验（2026-08-11）

## 结论

72 条平衡先导查询已由一名审核者逐条确认并冻结。最终选择 B2.1-safe“规则直通 + 显式复合证据门控 + Prompt V4 + 确定性安全仲裁 + 本地 LLM”：Accuracy 62.50%，Macro-F1 60.63%，LLM 调用率 38.89%。该版本不追求开发集最高路由分数，而以通过下游不退化门槛为先。

曾取得 Accuracy 70.83%、Macro-F1 70.14% 的无安全仲裁版本已淘汰，因为它在 V18 校准回归集上使正例来源 Top-1 下降 12.5 个百分点。该失败结果保留用于说明只优化路由分类指标会产生系统级退化。

## 数据治理

- 六类路由各 12 条，共 72 条，查询 ID 与查询文本均唯一。
- 审核结果：72 条接受建议标签，0 条修订，0 条缺失。
- 冻结文件：`data/evaluation/v19/pilot/queries_reviewed.csv`。
- 冻结回执：`data/evaluation/v19/pilot/review_freeze_receipt.json`。
- 当前只有一名审核者；正式 240 条数据仍需按协议执行部分双重标注。
- 先导集参与了门控、Prompt 与仲裁误差分析，不得作为 V19 最终效果声明。

- Accuracy 增加 23.61 个百分点。
- Macro-F1 增加 22.06 个百分点。
- 28 条调用子集中修复 17 条，未观察到相对 B0 的回退。
- 无效 JSON 率 0%，运行时回退率 0%。
- P95 低于 1500 ms 硬门槛，但没有达到 1000 ms 伸展目标。

## 下游回归

下游只复用 V18 的 80 条校准查询和冻结资料库，明确标记为回归诊断，不属于 V19 最终声明。通过冻结路由注入，只有路线变化的查询被重新检索，其余查询沿用相同基线结果。

### 被拒绝版本

- 路线变化 24/80。
- 正例来源 Top-1：下降 12.5 个百分点。
- 强负例来源 FAR@1：下降 20 个百分点。
- 结论：FAR 的下降来自过度切换到纯文字路线并丢失视觉正例，不是可靠改进，因此淘汰。

### 最终安全版本

- 路由调用 33/80，路线实际变化 7/80。
- 正例来源 Hit@1、Hit@3、Hit@10：相对 B0 均为 0 变化。
- 强负例来源 FAR@1、FAR@3、FAR@10：相对 B0 均为 0 变化。
- 结论：通过“下游不得退化”和“强负例 FAR 不得增加”门槛，但尚未证明检索收益。

## 误差与风险

- V18 校准集以复合视觉查询为主，B2.1-safe 的 LLM 调用率为 41.25%，略高于 40% 目标；正式六类平衡集仍需重新验证调用率。
- Prompt V4 明确区分真实场景中的空间关系与页面布局，并禁止把“查询由文字写成”误解为“候选页需要 OCR 文字”。
- 安全仲裁阻止无明确候选文字要求的视觉查询被降成纯文字/混合路线，也阻止长复合描述被降成短实体精确查找。
- RF 结果说明 72 条样本不足以训练监督式文本分类器；不再针对先导集调参。
- 下游回归仅验证“不退化”，最终检索效果必须由按释义族隔离的 V19 留出集决定。

## 决策

授权正式数据收集，但不授权最终效果声明。下一阶段冻结 Qwen3-1.7B、非思考贪心解码、`prompt_lookup_num_tokens=5`、Prompt V4、显式复合证据门控与安全仲裁，然后构建 240 条正式查询，按释义族划分 120 条校准集与 120 条单次留出集。
