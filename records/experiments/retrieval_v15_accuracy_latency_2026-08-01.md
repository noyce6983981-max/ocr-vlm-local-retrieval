# V15：复合视觉拒答与模型常驻加速

日期：2026-08-01

## 目标

V14.1 冻结测试确认两个产品问题：复合无答案查询会因单一 OCR 词勉强越过开放集门槛；首次文本查询还会启动与任务无关的视觉模型，冷启动 P50 为 38.71 秒。V15 在不改变冻结标签的前提下同时处理准确率和延迟。

## 实现

1. 文本证据查询只运行 BGE-M3 文字语义与 BM25，不再启动没有独立校准价值的视觉分支。混合查询与视觉查询仍保留原有三路证据。
2. 对包含“和、与、以及、同时、旁、顿号”等多概念关系的视觉请求增加首位候选视觉证据下限。候选只因其中一个 OCR 词命中、原始视觉分低于 0.35 时，系统明确拒答。
3. Streamlit 主站在后台预热一次 BGE-M3，并在不同查询间复用模型和 FAISS 索引；写入的仍是原有组件缓存格式，`live_search.py` 继续负责融合与门槛。
4. 常驻路径使用互斥锁保护模型推理；任何加载或评分异常都会自动回退到原有隔离 CLI，不影响可用性。
5. 未把现有多模态精排器放入快速路径。真实诊断中它单次启动超过 180 秒并超时，不满足交互延迟要求。

## 冻结回归

查询集、相关标签和 20 条测试分片与 V14.1 完全相同；`rq100_097` 与 `rq100_098` 的人工裁决仍未改动。

## 仍然存在的边界

- 隔离 CLI 的首次文字查询仍约 11 秒；网页依靠后台预热和模型常驻将不同新查询压到约 1 秒。
- 纯视觉首次查询仍需约 23–25 秒，因为 Qwen3-VL 视觉编码器尚未常驻。
- 冻结集只有两条无答案查询，100% 拒答不能外推为生产准确率。
- 新的生产准确率仍需依靠独立提出、未看过系统结果的查询集，不能用事后裁决成绩替代。
