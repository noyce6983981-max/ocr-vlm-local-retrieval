# 任意自然语言实时检索

## 目标

将项目从“预计算实验结果浏览器”升级为可输入任意新问题的真实本地检索系统。

## 实现

- BGE-M3对新问题生成1024维文本向量，并与38个OCR文本片段计算相似度。
- Qwen3-VL-Embedding-2B对同一问题生成2048维查询向量，并与24张图片计算相似度。
- 两个模型在独立环境中顺序运行，避免Windows CUDA依赖冲突和8GB显存同时占用。
- 根据每张候选图的OCR平均置信度进行质量自适应融合。
- 使用查询SHA-256摘要缓存结果，相同问题可直接返回。
- Streamlit提供输入框、四方法切换、Top-K图片和分支分数显示。

## 新问题测试1：纯视觉语义

查询：`哪张图片展示海边日落和水面倒影？`

该问题不在24条人工评测查询中。

| 方法 | Top 1 |
|---|---|
| OCR文本 | 观景台指示牌（错误） |
| Qwen3-VL视觉 | 海边日落风景（正确） |
| 固定融合 | 学术检索网页截图（错误） |
| OCR质量自适应融合 | 海边日落风景（正确） |

- 文本分支耗时：4.826秒
- 视觉分支耗时：11.318秒
- 含进程和模型加载的总耗时：33.659秒
- 重复查询缓存测试：约0.2秒

## 新问题测试2：场景文字

查询：`找出写着保护环境从我做起的红色横幅`

四种方法均将`pilot_020_environment_banner`排在Top 1，总耗时30.034秒。

## 结论

实时测试说明系统不再局限于预设问题：可以接收新的自然语言描述，并在现有24张图片中检索。纯视觉查询再次显示固定融合会受错误OCR文本影响，而质量门控能够保留正确视觉结果。

## 当前边界

- 只能检索当前已经建立索引的24张图片。
- 新图片上传与自动增量入库尚未实现。
- 两个模型按查询重新加载，首次查询约需20至40秒；后续可改为常驻服务降低延迟。
